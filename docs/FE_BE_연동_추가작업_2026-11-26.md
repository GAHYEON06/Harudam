# FE 기준 BE 추가 작업

FE는 읽기 전용으로 검토했다. FE의 여행 입력, 날짜 배치, 결과 화면은 샘플 데이터 또는 로컬 상태를 사용한다. 이번 변경은 BE만 대상으로 한다.

## 추가 기능
- travelApi/addPlaces: 확인된 장소 1~10개를 원자적으로 저장. 기존 requestId, expectedVersion, 소유권 검사 적용. 동일 sourceUrl 중복 거부. 서로 다른 URL이 동일 장소를 가리키는 경우까지 식별하지는 않는다.
- PlaceImportRepository: parsePlaces 응답을 Kotlin 모델로 변환. 부분 실패와 경고 제공.
- TravelViewModel: previewPlaces(urls) { batch -> ... }, saveImportedPlaces(places) { ... }.
- Emulator 테스트 추가: 일괄 저장, 재전송, 중복, 잘못된 입력, 권한 검사.

## FE 연결 순서
createTrip → previewPlaces → 사용자 확인 → saveImportedPlaces → confirmPlaces → setSchedule/reorderSchedule → getTrip.
previewPlaces는 저장하지 않는다. saveImportedPlaces 호출 전 선택된 여행이 필요하다. 카테고리 FOOD/TOUR/STAY/OTHER를 화면 레이블로 변환한다. 날짜는 YYYY-MM-DD.
네이버 개별 장소 링크만 지원하며 저장 목록 링크 및 실시간 파싱 성공은 보장하지 않는다.

## 검증 상태
GitHub 커밋만 완료. Android 빌드, Firebase Emulator 실행 및 운영 배포는 미실행. 기존 문서에 기록된 Blaze 요금제 제한 해결 여부는 미확인. FE 화면 연결은 별도 작업이다.
